## Context

本变更的动机和范围见 `proposal.md`，行为契约见 `specs/local-diagnostics-center/spec.md`。

当前应用的故障路径跨越 Tauri 生命周期、Win32 原生桌宠窗口、快捷面板 WebView、统计采集器和插件管理器。现有状态已经分散在 `PetHandle`、`QuickPanelController`、`CollectorHandle` 和 `PluginManager` 中，部分状态还带有 `last_error`，但错误大多只输出到标准错误或浏览器控制台。诊断功能必须在这些模块之上增加统一的接入点，而不是让每个调用方自行拼装日志格式。

桌宠启动后应继续保持轻量。诊断中心和相关 WebView 只能按需创建，日志写入不能阻塞桌宠窗口线程、采集器线程或 Tauri 主线程。

## Goals / Non-Goals

**Goals:**

- 以一个有深度的小接口统一 Rust、Win32 和前端事件、内存缓冲、文件日志、状态快照、panic 记录和诊断导出。
- 让发布版具备必要的本地排错能力，同时把详细日志和 WebView DevTools 放在显式的开发者模式下。
- 保证导出的诊断材料可供 AI 阅读，并在本地完成稳定、可测试的脱敏。
- 复用现有桌宠、快捷面板、采集器和插件状态，避免复制第二套业务状态。
- 让日志或诊断文件损坏、不可写或部分缺失时应用仍可运行。

**Non-Goals:**

- 不建立云端日志服务、遥测管道、账号体系或自动崩溃上传。
- 不把完整使用统计写入诊断文件，也不改变现有 SQLite 数据模型。
- 不为原生 Win32 桌宠窗口引入 WebView 或远程调试协议。
- 不在本变更中增加插件权限、插件执行能力或市场目录能力。

## Decisions

### 1. 在 `DiagnosticsManager` 处设置唯一外部接入点

新增一个由 Tauri `App` 管理的 `DiagnosticsManager`，对调用方暴露少量操作：

```text
record(event)
recent(query)
snapshot()
set_config(config)
export(request)
session_start() / session_end()
```

事件模型、关联 ID、级别过滤、脱敏、缓冲、持久化和导出都隐藏在该模块内部。调用方不直接依赖文件路径、日志库或压缩包格式。状态快照通过管理器内部的 provider 读取 `PetHandle`、`QuickPanelController`、`CollectorHandle`、`PluginManager` 和 Tauri 窗口状态；provider 失败只标记对应状态为不可用，不使整个快照失败。

这样可以把跨层复杂度集中在一个 seam 上，后续替换日志库或导出格式时不需要修改所有业务模块。

### 2. 采用 Tauri 官方日志插件作为输出适配器，事件格式由应用掌控

使用 Tauri 官方 `tauri-plugin-log` v2 提供平台日志目录、文件轮转、标准输出和可选 WebView 输出能力。`DiagnosticsManager` 仍是唯一事件入口，负责把 `DiagnosticEvent` 序列化为 JSONL，并将同一事件交给内存环形缓冲和日志适配器。

默认配置为 `info` 级别、单文件约 2 MB、最多保留 5 个归档文件，总日志占用约 10 MB。普通模式不启用 `debug/trace`；开发者模式通过 manager 的配置改变过滤级别。WebView 输出只用于开发者查看，不作为持久化的唯一来源。

选择该适配器是为了复用 Tauri 的 Windows 日志目录和轮转实现，同时避免业务代码依赖插件 API。没有必要为第一版引入 OpenTelemetry、Sentry 或完整的远程 tracing 系统。

### 3. 统一事件模型和关联 ID

`DiagnosticEvent` 使用 UTC 时间戳，字段至少包括：

```text
timestamp, level, module, event, message
errorCode?, windowLabel?, pluginId?, correlationId?, durationMs?, context?
```

前端命令入口生成关联 ID，并把它传给 Rust；没有前端入口的后台事件生成新的关联 ID。Rust 原生线程、快捷面板回调和插件操作继续沿用该 ID，避免依赖线程 ID 或窗口标题来拼接链路。`context` 只能使用经过 schema 校验的键值，未经允许的任意对象会被丢弃或转换为摘要。

高频操作只记录开始、结束、状态变化和错误。统计采集器每两秒的正常采样、桌宠动画帧和面板轮询不得进入事件流。

### 4. 使用本地文件和原子会话标记处理恢复

诊断目录位于 Tauri 的应用本地数据目录，文件模型为：

| 文件 | 用途 |
| --- | --- |
| `logs/diagnostics.log` 及轮转文件 | 结构化事件 JSONL |
| `diagnostics-settings.json` | 日志级别和开发者模式设置 |
| `session-state.json` | 当前会话是否已正常结束 |
| `last-crash.json` | 最近一次 panic 或异常退出摘要 |

设置和会话标记使用临时文件写入、同步后原子替换，沿用插件注册表的恢复思路。启动时先读取上一份会话标记：若仍为运行中，则生成一次异常退出事件；初始化成功后写入新的运行中标记；托盘正常退出和生命周期清理完成后写入正常结束标记。电源中断或强制结束留下的运行中标记可以在下次启动被识别。

日志文件损坏时跳过无法解析的行或文件并记录降级状态；`last-crash.json` 损坏时从诊断中心移除该记录但不得阻塞启动。日志写入通过有界异步队列执行，队列满时保留内存缓冲并递增丢弃计数，不让业务线程等待磁盘。

### 5. 将 panic 捕获放在生命周期和原生窗口两处

在构建 Tauri `App` 前安装全局 panic hook，记录线程来源、panic payload、时间和可用的 backtrace 摘要。Win32 `window_proc` 的 `catch_unwind` 保留安全回退行为，但在回退前通过不会再次触发 panic 的轻量路径写入事件和 `last-crash.json`。

panic 路径不能依赖正在关闭的 WebView 或可能已经中毒的业务 mutex；管理器提供一个只写文件的 fallback。异常摘要只保留最近一条，不创建内存转储，也不上传。

### 6. 诊断中心作为按需的独立 WebView 窗口

新增固定 label 的 `diagnostics` 窗口。托盘入口第一次点击时创建，后续点击复用并聚焦；关闭窗口只释放 UI，不停止日志和状态提供者。前端通过 Tauri commands 获取初始快照和分页日志，通过事件订阅接收新事件，关闭时取消订阅。

界面包含日志筛选、生命周期时间线、状态快照、最近错误、复制脱敏摘要、打开日志目录和导出诊断包。它不直接读取文件系统、不直接调用插件日志库，也不读取使用统计 SQLite。

### 7. 脱敏采用“结构化允许列表 + 最终文本清洗”两层策略

事件上下文优先使用允许列表，只保留错误码、插件 ID/版本、窗口 label、状态枚举和数值耗时。对错误消息、backtrace 和插件 I/O 错误执行最终文本清洗，替换 Windows 用户目录、机器名、绝对路径、盘符和常见凭据样式为稳定占位符（例如 `<user>`、`<machine>`、`<path>`）。

脱敏必须在写入导出包和复制摘要前再次执行，不能只依赖调用方自觉。应用内部日志可以保留更完整的本地错误信息，但诊断中心和导出接口只返回脱敏结果。插件 ID、版本、状态和错误码属于排错所需的最小信息，可以保留。

### 8. 开发者模式与发布版行为分离

保留 Debug 构建中的 `TAURI_DEV_MODE` 兼容入口，并增加持久化的本地设置。发布版默认关闭开发者模式；诊断中心和 `info/warn/error` 日志不受其影响。打开开发者模式后，manager 立即接收 `debug/trace` 事件，并在后续创建的诊断中心、完整统计、快捷面板和插件管理 WebView 上允许 DevTools。对已存在的窗口调用 Tauri 支持的打开操作；不支持动态启用的窗口在下一次创建时生效。

Debug 构建可配合 `TAURI_DEV_WINDOW=diagnostics|plugin-manager|dashboard` 指定启动时按需创建的诊断目标窗口，便于只通过终端和 WebView 只读调试接口采集日志；该入口必须与 `TAURI_DEV_MODE` 一起使用，并在发布构建中忽略。

桌宠本身是原生 Win32 窗口，开发者模式只能加强其结构化事件和 panic 记录，不能声称为它提供 WebView DevTools。

### 9. 诊断导出使用临时目录和固定文件清单

导出流程在应用数据目录创建临时目录，生成以下文件后压缩到用户选择的位置：

```text
summary.md
logs.jsonl
state.json
environment.json
last-crash.txt        (存在时)
```

`summary.md` 由最近错误、关联链、状态异常和环境摘要组成，控制长度并优先保留错误事件。导出前展示文件清单；任何一个可选文件缺失都在摘要中标记原因而不使导出失败。完成压缩后删除临时目录。打开日志目录使用系统 opener，不上传文件。

### 10. 资源和测试策略

常规模式下只保留固定大小的内存 ring（建议最多 500 条）和有界异步写入队列；诊断中心未打开时不创建额外 WebView。日志轮转、压缩和脱敏在后台执行。实现应提供事件格式、过滤、轮转、脱敏、会话恢复、快照部分失败和导出清单的纯 Rust 测试，并提供前端日志桥接和筛选测试。

## Risks / Trade-offs

- **[日志事件仍可能含有未知隐私内容]** → 结构化上下文采用允许列表，导出和复制前再执行路径/用户名/机器名清洗，并显示文件清单供用户确认。
- **[日志写入或压缩影响桌宠性能]** → 使用有界异步队列、固定 ring、默认 `info`、约 10 MB 文件上限，并禁止采样/动画逐条记录。
- **[panic 发生时普通日志设施不可用]** → 提供只写 `last-crash.json` 的 fallback，避免依赖 WebView、Tauri 事件和已中毒的业务锁。
- **[窗口在开发者模式切换前已经创建]** → 日志等级立即生效；DevTools 对当前窗口按 Tauri 能力尝试打开，对不支持动态启用的窗口在下次创建时生效。
- **[导出包仍可能被用户主动分享]** → 默认只保存到用户选定位置，不联网、不自动上传，并在界面明确提示导出内容已经脱敏但仍应人工检查。
- **[现有 `eprintln!` 与新事件重复]** → 迁移完成后把关键路径改为 manager 记录；短期保留标准错误输出仅作为开发构建 fallback，避免形成两个互不一致的诊断事实源。

## Migration Plan

1. 先加入日志依赖、诊断数据类型、内存 ring、文件适配器和测试，不改变现有统计数据库。
2. 接入生命周期、桌宠窗口、快捷面板、采集器、插件管理器和前端全局错误处理。
3. 增加诊断 commands、托盘入口和按需窗口，再接入开发者模式与 DevTools 控制。
4. 在 Windows 10/11 x64 上验证正常启动、快捷面板开关、插件失败、日志目录不可写、panic 恢复和诊断包导出。
5. 若需要回滚，移除诊断中心入口并关闭事件适配器即可；已生成的本地诊断文件可以保留，不迁移或修改使用统计数据。

## Open Questions

第一版固定使用单文件大小和归档数量上限，不提供用户自定义保留策略；如后续需要按天数或磁盘空间管理，再单独提出变更。当前没有会阻塞实现的开放问题。
