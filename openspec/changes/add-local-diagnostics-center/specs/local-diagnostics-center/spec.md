## Purpose

为桌宠提供一个本地优先、可脱敏导出的诊断能力，把 Rust、Win32、Tauri、WebView、采集器和插件运行时的故障统一成可筛选的事件与状态材料，方便用户和 AI 定位跨层问题。

## ADDED Requirements

### Requirement: 统一结构化诊断事件

系统 MUST 接受来自 Rust、Win32 原生窗口、Tauri 命令、Svelte/TypeScript 和插件运行时的诊断事件。每个事件 MUST 包含 UTC 时间戳、级别、模块、事件名和消息，并可包含错误码、窗口标签、插件 ID、关联 ID、耗时和脱敏上下文。

前端未捕获异常、未处理的 Promise rejection 和 Tauri 命令失败 MUST 进入同一诊断事件流；事件上下文不得包含未脱敏的用户路径、窗口标题或文档内容。

#### Scenario: 跨层操作使用同一个关联 ID

- **GIVEN** 用户从桌宠触发一个会创建快捷面板的操作
- **WHEN** 前端、Tauri 命令和快捷面板生命周期分别产生事件
- **THEN** 这些事件 MUST 可以通过同一个关联 ID 被检索并按时间顺序展示

#### Scenario: 前端异常进入诊断事件流

- **GIVEN** WebView 中发生未捕获异常或未处理的 Promise rejection
- **WHEN** 全局异常处理器捕获该异常
- **THEN** 系统 MUST 写入包含来源、错误级别和脱敏消息的诊断事件，且不得使桌宠退出

#### Scenario: 缺少可选上下文

- **GIVEN** 事件没有对应的窗口、插件或耗时信息
- **WHEN** 事件被记录
- **THEN** 事件 MUST 省略或置空这些可选字段，而不是填入误导性的默认值

### Requirement: 本地日志与最近事件缓冲

系统 MUST 将结构化事件写入应用本地数据目录的滚动日志文件，并保留一个有界的内存最近事件缓冲区。普通模式默认记录 `info` 及以上级别；`debug` 和 `trace` 级别 MUST 仅在开发者模式开启后生效。

日志文件 MUST 有单文件大小和保留数量上限，默认总占用不得超过 10 MB。事件写入失败时，系统 MUST 保留内存缓冲并在诊断状态中报告持久化降级，不得阻塞桌宠主线程或导致应用退出。

#### Scenario: 日志可在诊断中心检索

- **GIVEN** 系统已经记录了若干不同级别和模块的事件
- **WHEN** 用户打开诊断中心并设置级别、模块或时间筛选条件
- **THEN** 界面 MUST 只展示符合筛选条件的事件，并支持查看事件消息和结构化上下文

#### Scenario: 重启后保留日志

- **GIVEN** 应用在日志文件已经存在时正常退出或异常退出
- **WHEN** 应用下一次启动并打开诊断中心
- **THEN** 在保留策略范围内的历史日志 MUST 仍可被读取，损坏或不完整的单个日志文件不得阻止应用启动

#### Scenario: 日志持久化失败

- **GIVEN** 日志目录不可写或滚动文件操作失败
- **WHEN** 新事件继续产生
- **THEN** 系统 MUST 继续保留最近事件、显示日志持久化异常，并保持桌宠、统计采集和快捷面板可运行

### Requirement: 运行状态与生命周期时间线

诊断中心 MUST 提供一次性的运行状态快照，至少包含应用版本、构建模式、开发者模式、桌宠可见性、桌宠尺寸与皮肤、快捷面板状态、采集器状态、插件状态和已创建 WebView 窗口标签。快照 MUST 不包含完整使用统计记录、窗口标题或文档名。

系统 MUST 记录桌宠、快捷面板、采集器和插件的关键生命周期事件，但不得按动画帧或采集器每次采样写入高频日志。

#### Scenario: 空闲时暂停采集

- **GIVEN** 用户连续五分钟没有输入，且采集器进入空闲状态
- **WHEN** 采集器状态发生变化
- **THEN** 诊断时间线 MUST 记录一次进入空闲或暂停的状态事件，但不得把空闲期间写入为前台软件使用时长

#### Scenario: 锁屏或系统挂起

- **GIVEN** Windows 锁屏、注销或系统挂起导致采集器暂停
- **WHEN** 应用收到恢复或重新开始采集的生命周期信号
- **THEN** 诊断中心 MUST 展示暂停和恢复的状态变化，并保持使用统计口径不变

#### Scenario: 本地日期跨日

- **GIVEN** 应用在 Windows 本地日期跨日时仍然运行
- **WHEN** 诊断事件继续产生
- **THEN** 事件时间 MUST 继续以 UTC 保存，诊断时间线不得修改已有事件的时间；统计日期仍由采集器按本地日期计算

### Requirement: Panic 与异常退出记录

系统 MUST 安装 panic 记录机制，捕获 Rust 未处理 panic 和 Win32 原生窗口回调中被捕获的 panic，并保存最近一次异常摘要、来源、时间和可用的错误信息。应用启动时 MUST 检查上一次会话是否正常结束，并在发现异常退出时将其加入诊断时间线。

异常记录不得包含完整内存转储或自动上传数据；正常退出 MUST 不被标记为异常退出。

#### Scenario: 原生窗口回调发生 panic

- **GIVEN** Win32 桌宠窗口回调内部发生 panic
- **WHEN** 回调保护逻辑捕获该 panic
- **THEN** 系统 MUST 先记录带有来源和摘要的诊断事件，再执行安全的窗口回退行为

#### Scenario: 启动发现上次异常退出

- **GIVEN** 上一次会话没有写入正常结束标记
- **WHEN** 新会话启动并初始化诊断管理器
- **THEN** 诊断中心 MUST 显示一条上次异常退出记录，并允许用户将该记录包含在诊断摘要中

#### Scenario: 正常退出不生成误报

- **GIVEN** 用户通过托盘菜单正常退出应用
- **WHEN** 下次会话启动
- **THEN** 系统 MUST 不显示上一次异常退出提示，也不得生成新的 panic 记录

### Requirement: 诊断中心交互

系统 MUST 通过托盘菜单提供诊断中心入口，并保证同一时间最多存在一个诊断中心窗口。诊断中心 MUST 支持查看日志、查看状态快照、定位最近错误、复制脱敏摘要、打开本地日志目录和导出诊断包。

诊断中心按需创建，不得在桌宠启动时常驻额外的 WebView 窗口；关闭诊断中心不得停止日志记录或影响桌宠运行。

#### Scenario: 从托盘打开诊断中心

- **GIVEN** 桌宠正在运行且诊断中心未打开
- **WHEN** 用户从托盘选择诊断中心
- **THEN** 系统 MUST 创建并聚焦诊断中心窗口，展示当前状态快照和最近事件

#### Scenario: 重复打开诊断中心

- **GIVEN** 诊断中心窗口已经存在但不在前台
- **WHEN** 用户再次从托盘选择诊断中心
- **THEN** 系统 MUST 复用并聚焦已有窗口，不得创建第二个诊断窗口

### Requirement: 开发者模式与 WebView DevTools

发布版 MUST 默认关闭开发者模式、`debug/trace` 日志和 WebView DevTools，但普通诊断中心、必要的 `info/warn/error` 日志和诊断包导出 MUST 仍可用。用户 MUST 能在诊断中心中切换开发者模式并即时改变日志等级。

开发者模式开启后，系统 MAY 为诊断中心、完整统计、快捷面板和插件管理等 WebView 窗口提供 DevTools；桌宠原生 Win32 窗口不属于 WebView，不能以 DevTools 作为其诊断手段。

#### Scenario: 发布版默认状态

- **GIVEN** 用户首次启动发布版应用
- **WHEN** 应用完成初始化
- **THEN** 开发者模式 MUST 为关闭状态，普通日志和诊断中心可用，且不得自动打开 DevTools

#### Scenario: 即时开启详细日志

- **GIVEN** 用户已经打开诊断中心
- **WHEN** 用户开启开发者模式并选择 `debug` 或 `trace` 级别
- **THEN** 后续符合等级的事件 MUST 立即进入内存缓冲、日志文件和诊断中心，且不要求重启应用

### Requirement: 脱敏诊断包与 AI 摘要

系统 MUST 支持用户主动导出本地诊断包，至少包含脱敏摘要、结构化日志、运行状态、环境信息和最近异常记录（存在时）。导出前 MUST 展示待导出的文件清单，并在保存前执行统一脱敏。

诊断包 MUST 保存在用户选择的本地位置，系统不得自动上传或发送；复制摘要 MUST 使用与诊断包相同的脱敏规则。

#### Scenario: 导出完整诊断包

- **GIVEN** 日志、状态快照和环境信息可用
- **WHEN** 用户确认导出诊断包
- **THEN** 系统 MUST 生成包含 `summary.md`、`logs.jsonl`、`state.json`、`environment.json` 和可选 `last-crash.txt` 的本地压缩包，并报告保存位置

#### Scenario: 脱敏用户路径

- **GIVEN** 错误消息或插件错误上下文中包含用户名、机器名或绝对路径
- **WHEN** 用户预览或导出诊断包，或复制 AI 摘要
- **THEN** 这些值 MUST 被稳定替换为占位符，原始值不得出现在导出内容中

#### Scenario: 没有异常记录时导出

- **GIVEN** 当前会话没有 panic 或异常退出记录
- **WHEN** 用户导出诊断包
- **THEN** 系统 MUST 生成其他诊断文件，并明确标记最近异常记录不存在，而不是导出失败

### Requirement: 本地优先与资源上限

诊断能力 MUST 只使用本地存储，不得要求账号、网络连接、云同步或遥测许可。常规模式下诊断事件写入 MUST 使用异步或非阻塞路径，且不得记录动画帧、键盘内容、窗口标题、截图、网络活动或完整使用统计数据库。

诊断中心未打开时不得创建额外常驻 WebView；内存事件缓冲和滚动日志必须遵守已声明的数量与大小上限。

#### Scenario: 无网络环境

- **GIVEN** Windows 处于断网状态
- **WHEN** 用户查看诊断中心或导出诊断包
- **THEN** 诊断功能 MUST 正常工作，且不得因为网络不可用而重试上传或阻塞桌宠

#### Scenario: 高频采样不污染日志

- **GIVEN** 统计采集器按固定间隔采样，桌宠持续播放动画
- **WHEN** 采集器和动画继续运行
- **THEN** 诊断日志 MUST 只记录状态变化、错误和必要的生命周期事件，不得为每次采样或每一帧动画生成事件
