## Why

桌宠的故障可能发生在 Rust 生命周期、Win32 原生窗口、Tauri IPC、Svelte WebView、快捷面板、统计采集器或插件运行时。目前这些层没有统一的持久化日志、事件关联或状态快照，排错时只能依赖零散的 `eprintln!` 和浏览器控制台，AI 也无法还原窗口闪退前后的完整链路。

现在引入本地诊断中心，可以在不改变桌宠轻量主体验的前提下，把跨层故障整理成可筛选、可复制、可脱敏导出的诊断材料，并为发布版保留必要的排错能力。

## What Changes

### Included

- 新增本地诊断中心窗口，展示最近日志、生命周期事件、窗口状态、采集器状态和插件运行状态。
- 建立 Rust 与前端共用的结构化诊断事件模型，支持模块、事件名、错误码、关联 ID 和耗时等字段。
- 将日志写入本地滚动文件，同时保留有界的内存事件缓冲区，支持按级别、模块、窗口和插件筛选。
- 捕获未处理 panic、原生窗口回调中的 panic 和上次异常退出摘要。
- 支持导出脱敏的本地诊断包，并提供可直接复制给 AI 的诊断摘要。
- 增加开发者模式配置：动态提高日志级别，并在可用的 WebView 窗口开启 DevTools。
- 通过托盘入口访问诊断中心；不改变桌宠作为主界面的定位。

### Non-goals

- 不新增账号、云同步、远程日志上传、遥测或第三方崩溃平台接入。
- 不在诊断包中收集窗口标题、文档名、键盘内容、截图、网络活动、完整使用统计数据库或插件文件内容。
- 不把桌宠原生 Win32 窗口改造成 WebView，也不要求桌宠常驻打开开发者工具。
- 不在本变更中增加新的插件执行权限或插件市场能力。

### Privacy

诊断数据只写入本地应用数据目录。导出内容默认移除用户名、机器名、绝对路径和其他可识别信息；导出前显示文件清单，用户必须主动选择保存或复制。诊断中心不得自动联网或自动发送任何数据。

## Capabilities

### New Capabilities

- `local-diagnostics-center`: 提供统一结构化日志、运行状态快照、panic/异常退出记录、开发者模式和本地诊断包导出。

### Modified Capabilities

- 无。现有桌宠、统计和插件能力的用户可见需求不改变；本变更只增加诊断能力及其入口。

## Impact

- Rust：新增诊断管理模块，接入生命周期、Win32 桌宠窗口、快捷面板、统计采集器和插件管理器；增加 panic hook 与状态快照命令。
- Tauri：增加日志插件、诊断相关 commands、诊断中心窗口和托盘菜单入口；为可用的 WebView 窗口提供受控 DevTools 开关。
- Svelte/TypeScript：新增诊断中心界面、日志筛选、状态展示、复制摘要和导出交互；前端异常统一转发到诊断事件流。
- 本地文件：新增滚动日志、最近崩溃摘要和诊断导出文件；不修改现有使用统计数据库格式。
- 依赖：优先采用 Tauri 官方 `tauri-plugin-log` 作为日志输出适配器，结构化事件、脱敏和导出逻辑由应用自身负责。
- 兼容性：面向 Windows 10/11 x64，发布版默认保持普通日志级别和关闭 DevTools，开发者模式按需开启。
