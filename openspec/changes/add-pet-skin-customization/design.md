## Context

当前桌宠由 `src-tauri/src/pet_window.rs` 创建为独立的 Win32 透明窗口，角色通过单个内嵌 PNG 解码，再由现有 `FrameSet` 按 DPI、大小百分比和待机动作生成固定尺寸的预乘 BGRA 帧与 alpha 命中图。`PetHandle` 已经可以在线程间请求重建帧，快捷面板 `QuickPanel.svelte` 也已有设置视图和桌宠大小控制。

当前 `pet-preferences.json` 只保存版本 1 的大小百分比，并使用临时文件、`sync_all` 和 Windows 原子替换写入。完整统计采集和 SQLite 数据不应因为皮肤切换而改变。角色资源的现有边界是透明 RGBA、无背景、适合约 200 x 220 逻辑像素，并由窗口代码处理缩放和命中。

本设计承接 [proposal.md](./proposal.md) 的动机和 [pet-skin-customization spec](./specs/pet-skin-customization/spec.md) 的可观察行为，重点确定资源、原生窗口、前端设置和偏好存储之间的边界。

## Goals / Non-Goals

**Goals:**

- 让三套固定内置皮肤共享同一套帧生成、透明命中、DPI 和位置约束逻辑。
- 在快捷面板设置视图中提供本地缩略预览和即时切换，并保持当前大小、位置、统计采集和快捷面板生命周期。
- 在首次显示桌宠前恢复合法皮肤偏好，遇到损坏或不可用资源时安全回退到简洁云朵或上一套可用皮肤。
- 保持皮肤资源和选择数据完全离线，限制常驻内存和切换时的临时峰值。
- 让资源校验、偏好迁移、帧切换和错误回退可以在不创建 HWND 的情况下自动测试。

**Non-Goals:**

- 不建立用户上传、在线下载、商店、账号、云同步或可由用户编辑的通用主题系统。
- 不为每套皮肤引入独立的动画引擎、Live2D、骨骼系统或特殊窗口行为。
- 不重写统计采集、每日汇总、完整统计页或已有大小偏好的数据模型。

## Decisions

### 1. 使用静态类型化皮肤 manifest，并将资源随应用打包

在 Rust 侧新增一个皮肤资源模块，维护稳定的 `id`、中文名称、基准逻辑尺寸、主 PNG 和缩略 PNG 字节。三套首发 ID 固定为 `simple-cloud`、`orange-dragon` 和 `calico-cat`，manifest 顺序将简洁云朵放在第一位。主资源和缩略资源通过构建时内嵌，皮肤画廊通过 Tauri 命令读取同一 manifest 后返回名称、ID 和小型缩略图 data URL。

选择内嵌而不是运行时扫描目录，是因为桌宠待机路径不需要文件系统 I/O，不会受到安装目录权限、当前工作目录或资源路径变化影响，也不需要联网。三套资源的压缩 PNG 和缩略图都很小；只有当前皮肤的解码帧常驻，缩略图仅在快捷面板请求时通过一次 IPC 传输。manifest 的每个条目仍经过透明通道、尺寸、可解码性和缩略图校验；测试可以把缺失或损坏的字节切片传给相同校验函数来覆盖故障场景。

简洁云朵的例外来源为 `rullerzhou-afk/clawd-on-desk` 提交 `bca6a8d3f275df25d620367651502c6817a0c13b` 中的 `assets/gif/cloudling-idle.gif` 首帧。项目所有者已确认取得权利人书面授权，发布时的来源、固定提交和授权依据记录在 `src-tauri/assets/README.md`；橙色小龙和三花猫仍为项目自有原创资源。除这一经授权的例外外，参考目录中的其他素材不得进入发布包。

考虑过的替代方案：

- 从安装目录扫描 JSON manifest 和 PNG：支持以后添加文件，但增加启动 I/O、路径和安装完整性问题，当前三套固定皮肤不值得承担这套动态发现复杂度。
- 让 Svelte 前端各自维护缩略图清单：会产生 Rust 端和前端端的重复 ID，且桌宠可能显示一套前端可选但原生无法加载的皮肤。
- 直接把未经授权的 GitHub 参考素材打包：许可证和角色归属不适合作为产品资产；发布包只使用项目自有素材，或像 Cloudling 一样具有可核验授权依据的素材。

### 2. 复用现有原生帧管线，在线程内构建后再交换

桌宠线程保存当前 `SkinId`、当前大小百分比和 `FrameSet`。设置命令只把稳定 ID 发送给桌宠线程；线程校验 manifest、解码 RGBA、调用现有 `FrameSet::build`，并创建与新帧尺寸匹配的 GDI surface。只有候选帧、surface 和 alpha 图全部成功后，才在窗口线程一次性替换旧状态、重绘并按现有工作区规则重新约束位置。

切换沿用当前 DPI 和大小百分比，不通过 CSS 放大原生窗口，也不改变透明命中阈值。大小百分比固定为 30% 到 160% 的 10% 步进，默认值仍为 100%；前端、偏好文件和原生帧管线共用这一范围。快捷面板保持同一个窗口；桌宠尺寸或位置发生变化时复用已有锚点通知重新定位面板。前端在一次切换请求完成前禁用重复选择，原生侧仍使用请求代数丢弃过期结果，避免快速点击导致旧帧覆盖新选择。

考虑过的替代方案：

- 在 WebView 中显示角色并用 CSS 变换：无法复用 Win32 透明命中和现有桌宠窗口，缩放后边缘与点击区域也会分离。
- 为每套皮肤预生成八帧并在运行时切换：会让可执行文件和常驻内存按皮肤数量线性增长，并重复实现 DPI/大小变体；当前按源图重建更容易保持行为一致。

### 3. 皮肤偏好使用独立的本地文件

新增应用本地数据目录中的 `pet-skin-preferences.json`，格式固定为：

```json
{"version":1,"skin_id":"simple-cloud"}
```

皮肤文件与已有的 `pet-preferences.json` 分开保存。这样保留大小设置的版本 1 和旧版桌宠的读取能力，旧版本回滚时会忽略新增的皮肤文件，不会因为一次升级把大小偏好整体变成未知版本；同时大小保存失败不会覆盖皮肤选择，两个功能可以独立恢复。皮肤文件使用与现有大小偏好相同的临时文件、写入后 `sync_all`、Windows 原子替换和临时文件清理策略。

读取时只接受版本 1、清单中存在的稳定 ID 和严格的 JSON 结构；缺失、解析失败、未知版本、未知 ID 或资源校验失败都返回 `simple-cloud`。启动流程在创建第一组帧之前读取并规范化皮肤 ID。成功交换新帧后再更新内存中的当前 ID 并尝试保存；保存失败不撤销本次视觉切换，设置视图显示错误且保留上一份有效文件。成功保存后才认为偏好已持久化。

### 4. 通过 Tauri 命令提供最小的皮肤 API

在现有命令注册中加入三类接口：

- 查询可用皮肤清单，返回 ID、中文名称、缩略图 data URL 和当前可选状态。
- 查询当前皮肤 ID，用于设置视图初始化和启动回退反馈。
- 请求设置皮肤 ID，返回应用后的 ID、是否保存成功和可展示的错误消息。

命令只接受 manifest 中的稳定 ID，不接受路径、任意字节或远程 URL。错误码区分未知皮肤、资源加载失败、帧重建失败和偏好保存失败，前端据此保持当前选中项并显示简短中文反馈。命令不触碰 `CollectorHandle` 或 SQLite。

### 5. 在现有设置视图内加入画廊，不创建新的常驻窗口

`QuickPanel.svelte` 的设置视图在读取大小设置的同时读取皮肤清单；每套皮肤使用语义化按钮、缩略图、中文名称和当前选中标记。加载期间显示稳定的占位状态，资源不可用的条目不可点击；选择成功后立即更新选中状态和桌宠，选择失败则保留原选中项并使用 `role="alert"` 显示反馈。关闭快捷面板、返回今日概览或打开完整统计都不改变当前皮肤。

皮肤画廊不增加第二个 WebView 或全屏遮罩。快捷面板仍按需创建，关闭后缩略图 data URL 和组件状态随窗口释放；桌宠待机时只保留当前皮肤的原生帧。

### 6. 资源和内存预算

每套主资源限制在现有约 200 x 220 逻辑像素边界内，构建时拒绝没有透明像素、带不透明四角、超出合理尺寸或无法解码的 PNG。桌宠只保留当前皮肤的八帧、alpha 图和一个 GDI surface；切换时先构建候选帧再释放旧帧，因此临时内存峰值约为一套帧内存的两倍，而不是三套皮肤同时展开。以 160% 大小的当前基准为上限，候选帧的像素缓存控制在数 MiB 量级，切换完成后回到单套帧预算。

缩略图使用预先压缩的小尺寸 PNG，只有用户打开设置时才通过 IPC 传输。皮肤切换不启动新的采集线程、不创建新统计窗口，也不在待机定时器中重复解码。

## Risks / Trade-offs

- **[资源体积或帧峰值增加]** -> 限制主资源尺寸和缩略图大小，只为当前皮肤生成帧，切换完成后释放候选旧资源，并在 Windows 手工验证中记录待机 CPU 与私有工作集。
- **[快速连续选择造成旧结果覆盖新结果]** -> 前端串行化选择请求，原生线程使用请求代数，只提交最后一个仍有效的候选帧。
- **[皮肤资源损坏导致桌宠无法初始化]** -> manifest 启动校验；已选资源失败时回退到简洁云朵，单套切换失败时保留上一套可用帧，且不阻断托盘和统计采集。
- **[新增偏好文件写入失败]** -> 保留旧有效文件，清理临时文件，视觉切换仍可完成，并在设置视图明确说明重启后可能恢复旧皮肤。
- **[DPI、透明边界或源图比例不同]** -> 所有皮肤经过统一基准尺寸检查，继续使用既有 `FrameSet`、alpha 命中和工作区 clamp 测试；切换后发出已有锚点更新。
- **[第三方素材许可证不清晰]** -> 发布资产在任务验收时检查来源、许可证和授权依据；Cloudling 的固定提交、源文件与项目所有者确认的权利人授权记录在资源说明中，其他参考素材继续只保留在参考目录。

## Persistence and Recovery

- `pet-preferences.json`：继续由大小设置使用，格式和版本不变。
- `pet-skin-preferences.json`：版本 1，仅保存 `skin_id`；不保存选择次数、历史、统计数据或桌面内容。
- 内存状态：桌宠线程保存当前皮肤 ID 和当前帧；快捷面板只保存临时清单、加载状态和错误，不写入磁盘。
- 启动恢复顺序：读取皮肤偏好 -> 校验 manifest 与资源 -> 选择合法皮肤或简洁云朵 -> 读取大小并生成第一组帧 -> 创建可交互桌宠窗口。
- 运行时恢复顺序：候选资源和帧全部成功后交换；任一步失败则保留旧帧和旧 ID，不更新偏好文件。
- 偏好写入失败：只报告保存失败，不回滚本次运行的视觉状态；下一次启动继续读取上一份完整文件并按规则恢复或回退。

## Migration Plan

1. 将 `assets/gif/cloudling-idle.gif` 的已授权待机首帧迁移为简洁云朵主资源，并新增橙色小龙、三花猫的项目自有原创资源和缩略图；不迁移或复制其他未获授权的参考仓库角色文件。
2. 引入静态 manifest、资源校验和 `pet-skin-preferences.json` 读写；现有用户没有该文件时自动使用简洁云朵。
3. 在桌宠启动、Tauri 命令注册和快捷面板设置视图中接入皮肤清单与切换流程，保持 `pet-preferences.json`、SQLite 和统计 API 不变。
4. 完成自动化测试后，在 Windows 10/11 x64 上验证首次启动、三套皮肤切换、重启恢复、损坏文件回退、大小/DPI/边缘位置、锁屏/挂起和面板关闭。

回滚时，旧版本会继续读取原有的 `pet.png` 和 `pet-preferences.json`，忽略 `pet-skin-preferences.json`；因此桌宠仍能以原角色启动，新增皮肤偏好不会阻塞旧版本。重新升级后，皮肤文件仍按版本 1 规则读取。
