## Why

仓库目前没有根级 `README.md`，外部读者无法快速看懂“小桌宠”是什么、当前已经完成什么、如何运行，以及它为什么会发展成可插件化的桌面伙伴。插件基础设施仍在开发中，因此现在需要建立一份事实准确、视觉明确且能持续更新的项目首页，同时严格区分已实现能力与路线图。

## What Changes

- 新增中文为主的根级 `README.md`，首屏使用“小桌宠”产品名、简短定位和真实桌宠截图，让桌宠而不是使用统计成为第一视觉信号。
- 增加“当前可用”功能概览，按仓库实际状态说明透明桌宠窗口、点击快捷面板、大小设置、本地使用统计和现有皮肤能力。
- 增加醒目的“可插件化桌宠”章节，用简洁架构图解释核心宿主、官方预设插件、`.petpack`、本地插件目录和未来 SDK 的关系。
- 为插件化内容增加统一状态标签，明确区分“已实现”“开发中”“规划中”；在 `add-plugin-system-foundation` 未完成前，不把插件安装、商店、启用/禁用或 SDK 写成已经可用。
- 增加真实截图或短动图，至少覆盖桌宠本体、点击后的快捷面板和使用统计；所有媒体使用仓库内相对路径、稳定尺寸和可读替代文本。
- 增加快速开始、环境要求、开发命令、项目结构、隐私原则、路线图、OpenSpec 开发方式、资源授权和贡献说明。
- 参考 DeepSeek Harness、Tauri、Microsoft PowerToys 和 `bat` 等成熟 README 的信息顺序，但使用符合本项目体量的精简结构，不复制其宣传文案或无关章节。
- 增加 README 内容核验清单，确保命令、功能状态、截图、链接、版本和隐私描述可以从当前仓库验证。

### 非目标

- 不在本次变更中实现插件宿主、插件商店、在线目录、SDK、自动更新或任何新的桌宠功能。
- 不把尚未完成的 OpenSpec 任务写成已经发布的能力，也不承诺发布日期、下载地址或兼容性范围之外的平台。
- 不添加无法验证的下载量、性能、用户数量、安全性或“完全支持第三方插件”等宣传性结论。
- 不创建依赖外部服务的无效徽章，也不链接当前仓库不存在的发布页、贡献指南或许可证文件。
- 不把 README 扩展成完整用户手册、插件 SDK 文档或详细架构参考；这些内容只提供短摘要和稳定入口。

## Capabilities

### New Capabilities

无。本变更只新增和整理项目文档，不改变用户可观察的软件行为；`.openspec.yaml` 已设置 `skip_specs: true`。

### Modified Capabilities

无。README 只描述当前事实和已明确的开发路线，不修改桌宠、统计、皮肤或插件系统规格。

## Impact

- 新增根级 `README.md`，并可能新增专门用于 README 的压缩截图或短动图目录。
- README 会引用 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 和相关 OpenSpec 变更中的可核验信息。
- 现有 `src-tauri/assets/README.md` 继续负责皮肤资源来源与授权细节，根 README 只给出摘要和链接。
- 不修改 Rust、Svelte、TypeScript、SQLite 数据模型、Tauri 配置或应用运行行为。

## Privacy Impact

本变更只写入仓库文档和本地媒体资源，不新增数据采集、网络请求、遥测、账号或云同步。README 必须准确说明现有本地优先隐私边界，并在制作截图时避免包含用户名、绝对路径、窗口标题、私人应用记录或其他桌面敏感内容。
