## 背景

这是空项目中的第一个数据能力实现。行为契约位于 `specs/daily-app-usage/spec.md`，主要约束是 Windows 前台识别、本地存储、确定性的时间计算，以及较低的后台资源占用。

应用分为两种运行状态：长期运行的桌宠/采集器进程，以及按需打开的统计面板 WebView。Bun 只负责开发脚本和前端构建，发布包中不携带 Bun 运行时，也不启动 HTTP 服务。

## 目标与非目标

**目标：**

- 在桌宠运行时保持一个原生采集器，统计面板不打开时不常驻 WebView。
- 让时间归属、跨日处理和异常恢复逻辑可以通过确定性测试验证。
- 把数据库和 Windows 进程查询收敛在 Rust 边界内。
- 提供一个紧凑的中文每日统计面板，不引入图表或复杂组件库。
- 让未来的桌宠互动不依赖统计逻辑和持久化逻辑。

**非目标：**

- 为跨平台采集器建立通用抽象；本 change 只保留可测试的 Windows 适配边界。
- 时间线、分类推断、生产力分析、插件系统或同步接口。
- 亚秒级的前台切换精度；每日汇总允许一个采样间隔以内的误差。

## 技术决策

### 使用 Rust 采集器和按需创建的统计面板

Tauri 负责托盘、生命周期、单实例和统计窗口。Rust 采集器在创建任何面板之前启动。用户点击托盘或桌宠入口时创建一个 `WebviewWindow`；关闭面板时销毁窗口，而不是仅仅隐藏。桌宠主窗口由另一个 change 负责，统计面板不应取代它。

Svelte、TypeScript 和 Vite 负责统计面板，Bun 负责依赖安装、检查和构建。生产包只包含静态前端资源和 Rust 可执行文件。

替代方案：

- Electron 便于全部使用 TypeScript，但隐藏时仍保留 Chromium 和 Node，难以满足低资源目标。
- Bun sidecar 加浏览器界面会增加一个进程、RPC 生命周期和本地网络边界，不适合这个单机应用。
- 始终隐藏 WebView 会让重新打开更简单，但会持续支付 WebView2 的内存成本。

### 使用显式消息连接采集器和统计查询

独立工作线程拥有采样状态和 SQLite 连接。Tauri 命令发送 `GetDailyUsage`、`GetStatus` 和 `Shutdown` 等类型化消息并等待类型化回复。这样 SQLite 只有一个写入者，前端也不会直接访问数据库或本机路径。

领域模块接收平台无关的快照：单调时间、UTC 时间、本地日期/偏移、前台软件身份、输入空闲时长和 Windows 可用状态。Windows 适配器只负责产生快照，时间归属模块负责决定是否计入。这样测试不需要真实前台窗口或真实系统时钟。

模块关系保持简单：

```text
Tauri 生命周期/托盘/命令
          |
          v
采集器工作线程 ----> Windows 快照适配器
          |
          +----------> 时间归属状态
          |
          +----------> SQLite 仓储

统计面板 --类型化 invoke--> Tauri 命令
```

### 每两秒采样，并拒绝不确定的长间隔

Windows 适配器每两秒读取前台窗口、所属进程、`GetLastInputInfo` 和当前输入桌面。只有当前台身份变化时才解析可执行文件路径和版本资源描述，并缓存结果。采集器自身进程以及安全桌面不计入。

时长使用 Rust 的 `Instant` 计算。连续采样间隔超过十秒时认为这段时间不确定，不产生软件时长，避免睡眠、休眠、调试暂停或严重调度延迟造成虚假记录。正常跨午夜时，将采样区间拆到两个本地日期；系统时钟或时区发生跳变时，从新日期开始记录，不修改已经保存的日期汇总。

选择轮询而不是全局 WinEvent hook，是因为每日统计不需要亚秒级精度，轮询 API 成本很低，且避免了回调生命周期和原生消息循环的复杂性。如果资源实测不达标，只替换采样触发方式，不改变领域层接口。

### 从可执行文件建立软件身份

适配器通过前台窗口得到进程 ID，以查询权限打开进程并读取可执行文件路径。规范化后的不区分大小写路径作为稳定身份。保存的软件展示元数据包括可执行文件名，以及 Windows 文件描述/产品名；如果没有描述就使用可执行文件名。路径不会发送给前端，也不会传输到网络。

相比只使用显示名，这种身份更稳定；相比首版就解析所有打包应用的 AUMID，实现更简单。受保护或已经退出、无法查询的进程直接跳过，不猜测身份。

### 只保存每日汇总

Rust 直接使用 `rusqlite`，通过 `PRAGMA user_version` 管理 schema 版本。启用外键、忙等待、WAL 日志和 `synchronous=NORMAL`。第一版表结构如下：

```sql
CREATE TABLE applications (
  id                INTEGER PRIMARY KEY,
  identity_key      TEXT NOT NULL UNIQUE,
  executable_path   TEXT NOT NULL,
  executable_name   TEXT NOT NULL,
  display_name      TEXT NOT NULL,
  first_seen_utc    TEXT NOT NULL,
  last_seen_utc     TEXT NOT NULL
);

CREATE TABLE daily_usage (
  local_date        TEXT NOT NULL,
  application_id    INTEGER NOT NULL REFERENCES applications(id),
  active_ms         INTEGER NOT NULL CHECK (active_ms >= 0),
  updated_at_utc    TEXT NOT NULL,
  PRIMARY KEY (local_date, application_id)
);
```

采集器在内存中累积增量，每 30 秒在一个事务中写入软件元数据并增加 `active_ms`。只有事务提交成功后才清除待写入增量；写入失败时保留增量、进入错误状态并在下一次间隔重试。托盘退出会请求最后一次保存。进程崩溃最多丢失当前尚未提交的缓冲，不会在重启后虚构一段连续使用时间。

选择每日汇总而不是原始时间段，是因为当前唯一查询就是按日统计。这样可以减少隐私细节、磁盘写入、数据增长和跨日恢复复杂度。以后需要时间线时，应新增独立 schema change。

### 只向前端暴露汇总模型

前端接收的是汇总模型，而不是数据库行或本机路径：

```text
DailyUsageSummary
- date: YYYY-MM-DD
- trackerState: recording | idle | unavailable | error
- totalActiveMs: integer
- applications[]
  - displayName: string
  - executableName: string
  - activeMs: integer
  - share: number from 0 through 1
```

`GetDailyUsage` 将已提交数据与内存待写入增量合并一次，按时长降序、名称升序排序，并根据合并后的总时长计算占比。面板打开时查询今天并在可见期间刷新；日期只能向过去切换，不能进入未来。

### 统计面板保持紧凑、中文和低依赖

统计面板约为 460×620 逻辑像素，并设置可用的最小尺寸。内容包括日期工具栏、记录状态和总时长摘要，以及带时长、占比和 CSS 进度条的软件列表。界面使用系统字体、跟随 Windows 明暗偏好，所有可见产品文案使用简体中文。

不引入图表库、动画运行时、远程字体或宠物资源。加载、空数据和保存异常状态必须保持稳定尺寸，避免刷新时布局跳动。

### 单实例和本地行为

使用 Tauri 单实例支持，第二次启动只通知现有进程打开或聚焦桌宠/统计面板，不启动第二个采集器或数据库写入者。托盘提供打开和退出。内容安全策略只允许打包资源和 Tauri IPC，不允许远程连接；前端不包含 HTTP 客户端、分析 SDK、更新器或远程字体。

SQLite 文件位于 Tauri 的每用户本地应用数据目录。正常卸载可以保留这个本地数据库；安全删除和应用内清空历史属于另一个 change。

## 风险与取舍

- [两秒采样可能把前台切换误差分配到一个采样间隔] -> 集中管理采样间隔，并测试每个区间最多归属一个软件。
- [受保护、提权或打包应用可能无法提供有用的可执行身份] -> 无法查询时跳过，使用可执行文件名作为展示回退，不读取窗口内容。
- [时钟、时区、夏令时和午夜逻辑容易出错] -> 时长使用单调时钟，日期分配单独实现，并用假时钟表驱动测试覆盖边界。
- [写入失败可能让内存中积累超过 30 秒的数据] -> 显示错误状态，保留待写入增量并持续重试，不声称数据已经持久化。
- [销毁并重建 WebView2 会增加面板冷启动时间] -> 接受这点延迟，换取桌宠全天候更低的内存占用，并单独测量冷启动和后台内存。
- [50 MiB 目标依赖构建模式和 Windows 环境] -> 使用 release 构建，在面板销毁后用固定 PowerShell 步骤测量。

## 迁移计划

1. 在每用户应用数据目录创建第一版 SQLite schema。
2. 采集器和统计面板一起发布；当前没有旧数据需要迁移。
3. 如果 schema 初始化失败，保留数据库文件，进入错误状态，不向未知 schema 写入。
4. 回滚方式是退出并卸载应用。默认保留 SQLite 文件，重新安装同版本可以继续读取；用户可以手动删除应用数据目录来永久清除。
