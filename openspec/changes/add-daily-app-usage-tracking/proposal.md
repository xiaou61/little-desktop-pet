## 为什么

用户需要一种私密、低资源的方式，了解每天把活跃电脑时间花在了哪些软件上。这个 change 建立本地使用统计基础，但它是桌宠的附属能力，不是产品主界面。

## 变更内容

- 增加 Windows 后台采集器，在桌宠运行期间记录前台软件的活跃时长。
- 用户连续五分钟没有输入、锁屏、系统挂起或无法识别前台进程时，不计入对应时段。
- 保留一个紧凑的每日统计面板，展示选中日期、记录状态、总时长，以及每个软件的时长和占比。
- 使用本地 SQLite 保存每日汇总；异常终止时最多丢失最近一次保存间隔内尚未落盘的记录。
- 采集器与桌宠主窗口解耦，统计面板按需打开，关闭面板后后台采集继续运行。

## 非目标

- 在本 change 中定义桌宠主界面、角色资产和角色动画；这些内容由 `add-desktop-pet-shell` change 负责。
- AI 对话、提醒、目标、应用阻断、生产力评分或完整时间轴。
- 账号、遥测、云同步、局域网服务或远程访问。
- 窗口标题、文档名、键盘、鼠标内容、截图、网址或网络活动采集。
- 跨平台支持、可配置空闲阈值和数据导出。

## 能力

### 新增能力

- `daily-app-usage`：在桌宠后台本地收集前台软件活动，并按本地日期提供每个软件的累计时长。

### 修改能力

无。

## 隐私影响

应用只在用户本地应用数据目录中保存本地日期、软件身份元数据、活跃时长、状态和必要的持久化时间戳。可执行文件路径可能包含用户名等本机目录信息，因此路径只留在本地，不会进入前端展示，也不会通过网络发送。应用不读取或保存窗口内容和用户输入。

## 影响范围

- 使用 Tauri 2、Rust、Svelte/TypeScript、Bun 和本地 SQLite。
- 通过 Rust 的 Windows API 适配层读取前台窗口、进程元数据和输入空闲状态。
- 依赖 Windows 10/11 x64；只有打开统计面板时才需要创建 WebView2 窗口。
- 建立本地数据表，以及桌宠/统计面板与采集器之间的内部 Tauri 命令边界。
