## 背景

现有桌宠是独立的 Win32 分层窗口，完整统计页是按需创建的 Tauri `WebviewWindow`；桌宠线程目前只向主线程发送点击回调，位置和帧尺寸使用物理像素。此次变更需要在不让桌宠常驻 WebView 的前提下增加一个短暂存在的交互面板，并让原生角色可以安全地重建为不同大小。详细用户行为以本变更的两个 spec 为准。

## 目标与非目标

**目标：**

- 快捷面板只在需要时创建，打开时可快速读到今日概览，关闭后不留下输入拦截层。
- 让面板与桌宠保持稳定的锚定关系，正确处理翻转、工作区边界、DPI 和多显示器。
- 让 70%–160% 的大小调整即时反馈，并复用现有桌宠的透明命中和位置约束逻辑。
- 保持后台采集、完整统计页和现有隐私边界不变。
- 让纯几何、百分比规范化、配置读写和交互状态可以在无 HWND 的测试中验证。

**非目标：**

- 不把桌宠本体改成 WebView，也不引入常驻的全屏透明遮罩。
- 不在本次变更中重写完整统计页、采集器或 SQLite 数据模型。
- 不建立通用主题系统、任意自由缩放或跨平台玻璃材质抽象。

## 技术决策

### 使用独立、按需创建的快捷面板窗口

快捷面板使用独立的 Tauri `WebviewWindow`，固定标签（例如 `quick-panel`），启动时不创建。第一次点击时在主线程创建并加载轻量 Svelte 视图；再次打开只更新数据和位置，关闭时销毁窗口或释放其 WebView，不使用隐藏的常驻面板。完整统计页继续使用现有稳定标签，设置视图放在快捷面板内部或其同一窗口的视图状态中。

选择按需 WebView 是因为面板需要可靠的中文排版、按钮、键盘焦点和无障碍语义，而这些能力不值得在 Win32 原生层重新实现。面板短暂增加的 WebView2 内存只发生在用户主动查看时，桌宠待机资源预算仍按关闭面板的状态测量。

考虑过的替代方案：

- 在原生桌宠窗口中直接绘制文字和按钮：常驻资源较低，但需要自行处理字体、输入、焦点、无障碍和国际化，超出本版范围。
- 使用覆盖整个屏幕的透明 WebView 捕获外部点击：实现关闭逻辑较简单，但会拦截桌面输入、增加窗口面积，也违背面板轻量和透明区域穿透要求。
- 让点击直接打开完整统计页：复用代码最多，但反馈过重，不符合桌宠主体验。

### 用锚点 DTO 和纯函数计算面板位置

原生桌宠线程在点击、拖动结束、DPI 变化和显示器变化后，向主线程提供一个只读的 `PetAnchor`：桌宠物理像素矩形、所在工作区矩形、当前 DPI 和可见状态。主线程把面板的逻辑尺寸转换为同一 DPI 下的物理尺寸，再调用纯函数按以下顺序计算：

1. 以桌宠矩形的下边缘加固定间距作为首选位置。
2. 若面板无法完整落在工作区，则尝试桌宠上边缘减面板高度。
3. 对最终坐标执行水平和垂直 clamp；若工作区小于面板尺寸，仍保证面板左上角落在工作区内。
4. 只把计算结果传给 WebView 窗口，不让前端自行读取屏幕坐标。

几何函数使用物理像素输入输出并覆盖下方充足、上方翻转、左右边缘、负坐标显示器和 DPI 改变等单元测试。面板首次渲染后若实际尺寸与预估尺寸不同，窗口控制器最多执行一次重新定位，避免尺寸和位置之间的循环更新。

### 采用系统 Backdrop，失败时回退

面板窗口保持无边框、不可调整大小、跳过任务栏并置顶。Windows 11/支持的 Windows 10 环境优先通过现有 `windows` crate 的 DWM 能力设置 Acrylic/Transient Backdrop，CSS 只负责半透明前景、边框和内容层；设置失败或系统关闭透明效果时，使用高不透明度的纯色背景。这样玻璃效果不会成为面板可用性的前置条件，也不需要引入远程资源。

面板背景不使用大面积渐变或装饰性模糊球。打开和关闭只使用短暂的透明度、轻微缩放过渡；通过 `prefers-reduced-motion` 以及系统减少动画状态跳过过渡。颜色、文字和焦点样式必须在透明效果关闭时仍满足可读性。

### 通过稳定的 Tauri 事件处理关闭和入口跳转

桌宠短单击由原生线程回调到主线程，主线程统一执行快捷面板的显示、关闭和定位。面板窗口失去激活状态时触发外部关闭，但控制器要区分面板内部的焦点切换，避免点击按钮时先被关闭；前端捕获 `Escape` 后调用同一个关闭命令。点击“查看完整统计”先记录动作，再关闭快捷面板并聚焦唯一统计窗口；点击“设置”只切换设置视图，不创建第二个桌宠或采集器。

所有窗口创建和销毁都在 Tauri 主线程完成。面板控制器持有一个短生命周期状态，包含当前打开状态、最后一次 `PetAnchor` 和代数标识；异步数据响应必须校验代数，防止关闭后旧响应重新显示面板。

### 扩展桌宠帧生成而不是缩放窗口内容

大小百分比在 Rust 侧规范化为 70–160 的 10% 步进。`FrameSet::build` 在现有 DPI 缩放之后再应用百分比，生成新的预乘 BGRA 帧、alpha 命中图和 GDI surface；窗口外部尺寸与帧尺寸同步更新，待机动画仍使用同一组固定尺寸帧，避免命中区域随每一帧跳动。调整期间暂停一帧动画，完成后调用同一个最近显示器 clamp 函数并通知面板重新定位。

缩放不通过 CSS 放大原生窗口，也不改变桌宠透明像素的阈值。这样拖动、点击和 DPI 变化继续沿用已经测试过的物理像素路径，且角色边缘不会因为 WebView 缩放而出现不同的命中结果。

### 使用独立的本地偏好文件

保持现有 `pet-state.json` 只保存窗口位置，新增同目录的 `pet-preferences.json`：

```json
{"version":1,"size_percent":100}
```

偏好文件采用临时文件写入、`sync_all` 和 Windows 原子替换。读取时拒绝未知版本、无法解析、越界或非 10% 步进的值并回退到 100%；旧版本没有该文件时也使用 100%。桌宠启动时先读取并规范化偏好，再构建第一组帧，避免先以错误尺寸显示或拦截桌面输入。

成功应用大小后立即更新内存状态并尝试保存。保存失败不撤销本次运行的视觉调整，但向设置视图返回明确的本地保存错误，并保留原有有效文件，提示重启后仍会使用上一次成功保存的值。偏好只在成功应用值时写入，不保存面板打开次数或点击轨迹。

### 保持统计接口和资源预算

快捷概览直接调用现有的今日汇总命令，在前端按时长排序并截取最多三条，不新增第二套采集查询或数据库表。完整统计入口复用已有窗口控制器。面板关闭后运行五分钟资源测试；同时增加面板打开状态的手工检查，确认 WebView 只在需要时存在，关闭后桌宠的 CPU 和私有工作集回到原有预算。

## 数据模型与故障恢复

- `pet-state.json`：保持版本 1 的 `x`、`y` 位置数据，旧版本和回滚版本继续可读。
- `pet-preferences.json`：版本 1 的 `size_percent`，只允许 70–160 的 10% 步进。
- 面板状态：仅保存在进程内，包含是否打开、当前锚点和一次性窗口代数；关闭或进程退出即丢弃。
- 统计数据：继续由现有 SQLite 和 `get_daily_usage` 提供，不复制到偏好文件。

面板创建失败、玻璃材质失败、偏好文件损坏或大小重建失败都必须隔离在对应功能内：桌宠仍可拖动、托盘仍可显示/隐藏和打开完整统计，采集器不停止。若新帧无法构建，则保留上一次可用帧和大小，设置视图显示错误，不写入损坏偏好。

## 风险与取舍

- [DWM Backdrop 在不同 Windows 版本表现不同] -> 将材质设置视为增强效果，启动后检测能力，始终准备高不透明度回退并覆盖对比度检查。
- [面板失焦事件与桌宠点击存在竞态] -> 所有打开/关闭动作经过主线程控制器串行化，按钮动作先标记内部交互，再处理失焦事件，并以面板代数丢弃过期响应。
- [缩放重建帧可能暂时增加 CPU 和内存] -> 只在设置改变或 DPI 改变时重建，复用预计算帧和 GDI surface，待机期间不重复缩放。
- [偏好保存失败导致用户误以为已持久化] -> 设置视图展示保存结果；保留旧有效文件并明确说明本次运行与重启后的差异。
- [小尺寸面板在高 DPI 下文字拥挤] -> 设定稳定的逻辑尺寸、最小内边距和最多三条摘要，使用内容溢出省略而不改变窗口尺寸。

## 迁移与回滚

1. 不迁移 SQLite，不修改已有每日使用记录和采集器 schema。
2. 发布新版本时保留现有 `pet-state.json`；没有 `pet-preferences.json` 的用户从 100% 开始。
3. 回滚到旧版本时旧代码忽略 `pet-preferences.json`，继续使用原位置文件；新版本再次启动时仍可读取合法大小偏好。
4. 若新面板或大小功能初始化失败，运行时自动回退到现有桌宠、托盘和完整统计入口，不阻止应用启动。
