## Purpose

为桌宠提供可验证、可回滚的本地插件包生命周期，让用户能够从最小核心开始按需安装能力，同时避免损坏的资源包影响已经可用的桌宠和其他插件。

## ADDED Requirements

### Requirement: 插件包必须具有可验证的 manifest 和资源边界

系统 SHALL 只接受版本化的 `.petpack` 包；每个包 MUST 声明稳定插件 ID、插件版本、显示名称、宿主协议版本、插件类型、权限声明和贡献资源。系统 MUST 拒绝未知宿主版本、非法 ID、重复贡献 ID、绝对路径、路径穿越、超出资源大小限制或无法解码的资源。

#### Scenario: 导入合法资源插件包

- **GIVEN** 用户选择一个包含合法 manifest、透明 PNG 资源和唯一贡献 ID 的 `.petpack`
- **WHEN** 系统读取插件包
- **THEN** 系统接受该包的元数据和资源
- **AND** 插件可以进入本地安装流程
- **AND** 系统不要求启动网络连接

#### Scenario: 拒绝不兼容的插件包

- **GIVEN** 插件包声明的宿主协议版本不在当前支持范围内
- **WHEN** 用户尝试导入该插件包
- **THEN** 系统拒绝导入
- **AND** 显示不兼容原因
- **AND** 当前已安装插件和桌宠状态保持不变

#### Scenario: 拒绝越界路径和超限资源

- **GIVEN** 插件包包含 `../`、绝对路径、压缩展开后超出限制的文件或超大图片
- **WHEN** 系统执行插件包校验
- **THEN** 系统拒绝整个插件包
- **AND** 不在应用插件目录创建可执行或可引用的部分文件
- **AND** 不把该包记录为已安装

### Requirement: 插件安装必须具有原子性

系统 SHALL 在插件包通过完整校验后才提交安装结果；任何解压、校验、写入或注册失败 MUST 清理临时文件，并 MUST 保留当前版本和当前启用状态。

#### Scenario: 成功安装插件

- **GIVEN** 插件包通过 manifest、资源和宿主版本校验
- **WHEN** 用户确认安装
- **THEN** 系统将完整包登记为已安装版本
- **AND** 该插件的资源可以被宿主查询
- **AND** 注册表写入完成后才向界面报告成功

#### Scenario: 安装过程中写入失败

- **GIVEN** 插件包校验通过但目标目录或注册表暂时不可写
- **WHEN** 系统提交安装
- **THEN** 系统报告安装失败
- **AND** 删除本次安装产生的临时目录和临时注册表
- **AND** 已有插件版本和桌宠当前外观不发生变化

### Requirement: 插件状态必须支持可预测的生命周期迁移

系统 SHALL 为插件记录 `discovered`、`installed`、`enabled`、`disabled`、`broken` 和 `removed` 状态；状态迁移 MUST 只允许由有效的安装、启用、禁用、卸载或故障事件触发。重启后系统 MUST 按注册表恢复状态，不得把未安装的目录内容自动当成已启用插件。

#### Scenario: 首次启用已安装插件

- **GIVEN** 插件包已经完成安装且状态为 `installed`
- **WHEN** 用户确认启用插件
- **THEN** 系统验证其贡献并将状态更新为 `enabled`
- **AND** 插件贡献对宿主可见

#### Scenario: 禁用插件

- **GIVEN** 插件状态为 `enabled`
- **WHEN** 用户选择禁用
- **THEN** 系统移除该插件对宿主的贡献
- **AND** 将状态更新为 `disabled`
- **AND** 插件文件仍可用于之后重新启用

#### Scenario: 重启恢复状态

- **GIVEN** 用户在上次运行中禁用了一个插件
- **WHEN** 应用重新启动
- **THEN** 该插件保持 `disabled`
- **AND** 系统不因为插件目录仍然存在而自动启用它

### Requirement: 卸载和故障处理不得破坏核心兜底

系统 SHALL 允许用户卸载普通插件，但 MUST 保护核心宿主、插件管理器和最后一套可用默认皮肤不被卸载。插件启用或加载失败时，系统 MUST 将其标记为 `broken` 并保留错误信息，同时继续运行核心和其他可用插件。

#### Scenario: 卸载普通插件

- **GIVEN** 用户选择一个已禁用的普通插件并确认卸载
- **WHEN** 系统执行卸载
- **THEN** 插件不再出现在已安装清单中
- **AND** 其贡献不再提供给宿主
- **AND** 核心桌宠和其他插件继续运行

#### Scenario: 阻止卸载默认皮肤

- **GIVEN** 当前只有 `simple-cloud` 这一套可用皮肤
- **WHEN** 用户尝试卸载 `simple-cloud`
- **THEN** 系统拒绝该操作
- **AND** 说明必须保留至少一套可用皮肤
- **AND** 桌宠继续显示 `simple-cloud`

#### Scenario: 插件加载失败

- **GIVEN** 一个已启用插件的资源在启动后损坏或贡献校验失败
- **WHEN** 系统加载该插件
- **THEN** 系统将其标记为 `broken`
- **AND** 记录可供用户查看的错误原因
- **AND** 桌宠、插件管理器、其他官方插件和统计数据继续可用

### Requirement: 插件注册表和插件设置必须本地隔离

系统 SHALL 将插件安装状态、版本和校验信息保存在版本化本地注册表中，并 SHALL 为每个插件提供独立的设置命名空间。插件不得读取或写入其他插件的设置、使用统计数据库或桌宠核心偏好。

#### Scenario: 读取插件自己的设置

- **GIVEN** 一个已启用插件请求读取其设置
- **WHEN** 宿主处理该请求
- **THEN** 系统只返回该插件命名空间内的数据
- **AND** 不返回其他插件或核心偏好的内容

#### Scenario: 注册表损坏时恢复

- **GIVEN** 插件注册表缺失、无法解析或版本不兼容
- **WHEN** 应用启动
- **THEN** 系统跳过无法确认的插件启用状态
- **AND** 保留核心桌宠和默认皮肤可启动
- **AND** 用户可以从插件管理器重新导入合法插件包
