## Purpose

让桌宠核心保持轻量且可独立启动，把统计、面板、大小设置和外观等能力作为可组合的官方插件提供，同时用受控宿主能力隔离插件与 Windows 原生实现。

## ADDED Requirements

### Requirement: 首次启动必须保持极简并只启用一套默认皮肤

系统 SHALL 在首次启动时提供可交互的基础桌宠、插件管理入口和核心级默认皮肤；官方快捷面板、使用统计和大小设置可以作为预装并启用的官方插件。首次启动 MUST 只安装并启用 `simple-cloud` 这一套皮肤，其他官方皮肤只能作为未安装的目录条目出现。

#### Scenario: 新用户首次启动

- **GIVEN** 应用本地没有插件注册表或有效安装记录
- **WHEN** 用户启动应用
- **THEN** 桌宠可以显示、拖动、点击和隐藏
- **AND** `simple-cloud` 是唯一已安装并启用的皮肤
- **AND** 官方插件目录可以显示其他可安装皮肤
- **AND** 系统不需要网络才能启动核心桌宠

#### Scenario: 其他官方皮肤尚未安装

- **GIVEN** 用户首次启动后打开插件目录
- **WHEN** 系统展示橙色小龙或三花猫等官方皮肤
- **THEN** 它们显示为可安装而不是当前可用皮肤
- **AND** 用户确认安装并启用前，桌宠不会切换外观

### Requirement: 官方插件必须通过与第三方相同的贡献接缝装配

系统 SHALL 将使用统计、快捷面板、大小设置和皮肤能力作为可识别的官方插件贡献注册；除核心兜底外，宿主不得为官方插件保留一套绕过插件注册的特殊用户路径。官方插件可以使用受信任的原生适配器，但其对外行为 MUST 遵循与资源插件相同的生命周期、状态和错误反馈规则。

#### Scenario: 官方使用统计插件启用

- **GIVEN** 官方使用统计插件处于 `enabled` 状态
- **WHEN** 应用启动并开始采集
- **THEN** 宿主提供现有的前台活跃统计能力
- **AND** 统计继续只保存在本地
- **AND** 禁用该插件后，核心桌宠仍能运行

#### Scenario: 官方皮肤插件启用

- **GIVEN** 用户从目录安装并启用了另一套官方皮肤插件
- **WHEN** 该插件的资源贡献通过校验
- **THEN** 皮肤出现在可用皮肤清单中
- **AND** 用户可以通过宿主选择它
- **AND** 皮肤切换不创建第二个桌宠窗口或统计采集器

### Requirement: 插件只能通过受控宿主能力贡献功能

宿主 SHALL 提供版本化且可校验的桌宠、面板、设置、菜单、存储和权限能力；插件 MUST 只能声明宿主支持的贡献类型。插件不得直接获得 HWND、GDI、任意 Tauri command、SQLite 连接、任意文件路径、进程启动权或网络访问权。

#### Scenario: 注册声明式面板贡献

- **GIVEN** 插件声明一个宿主支持的面板卡片和一个固定动作 ID
- **WHEN** 宿主启用该插件
- **THEN** 快捷面板可以显示该卡片
- **AND** 动作只能调用宿主为该 ID 提供的受控行为
- **AND** 插件不需要访问 WebView 或窗口句柄

#### Scenario: 拒绝未支持的能力

- **GIVEN** 插件声明任意代码执行、网络访问或未注册的贡献类型
- **WHEN** 宿主加载插件
- **THEN** 宿主拒绝该贡献或将插件标记为 `broken`
- **AND** 不授予声明中的未支持权限
- **AND** 核心和其他插件继续运行

### Requirement: 插件生命周期必须可重复且不会产生重复宿主资源

系统 SHALL 在插件启用时注册其贡献，在禁用或卸载时撤销其贡献；重复启用同一插件 MUST 保持单份贡献、单个采集器、单个快捷面板和单个桌宠窗口。任何贡献初始化失败 MUST 回滚本次启用产生的部分状态。

#### Scenario: 重复启用同一插件

- **GIVEN** 一个官方插件已经处于 `enabled` 状态
- **WHEN** 用户再次执行启用操作
- **THEN** 系统保持一份该插件贡献
- **AND** 不创建第二个统计采集器、快捷面板或统计窗口
- **AND** 插件状态仍为 `enabled`

#### Scenario: 启用时部分贡献失败

- **GIVEN** 插件的设置贡献有效但面板贡献无法创建
- **WHEN** 用户启用该插件
- **THEN** 宿主撤销本次启用产生的设置贡献
- **AND** 插件进入 `broken` 状态并显示失败原因
- **AND** 之前已启用的插件和核心桌宠不受影响

### Requirement: 通用 IPC 必须覆盖动态插件管理而不暴露动态 command

系统 SHALL 提供稳定的通用插件 IPC，用于查询清单、查询贡献、安装、启用、禁用、卸载和执行宿主批准的动作。IPC 输入 MUST 使用插件 ID、贡献 ID 和动作 ID 等稳定标识，不得接受任意模块路径、脚本内容、远程 URL 或窗口句柄。

#### Scenario: 前端查询插件清单

- **GIVEN** 插件管理界面已打开
- **WHEN** 前端请求插件清单
- **THEN** 宿主返回已安装插件、状态、版本和可安装官方目录条目
- **AND** 返回值不包含本地绝对路径、访问令牌或内部窗口句柄

#### Scenario: 拒绝任意路径动作

- **GIVEN** 前端提交包含文件路径、脚本内容或远程 URL 的插件动作请求
- **WHEN** 宿主校验 IPC 输入
- **THEN** 宿主拒绝请求
- **AND** 不改变任何插件状态
- **AND** 不创建或访问请求中的路径和网络地址

### Requirement: 插件故障不得阻断桌宠核心和其他插件

系统 SHALL 隔离单个插件的解析、资源、贡献和持久化故障；插件失败时 MUST 保留核心桌宠的显示、拖动、点击、托盘和插件管理入口。皮肤插件失败时 MUST 保留上一套可用皮肤或核心默认皮肤。

#### Scenario: 启动时官方插件损坏

- **GIVEN** 官方快捷面板插件的资源无法加载
- **WHEN** 应用启动
- **THEN** 快捷面板插件进入 `broken` 状态
- **AND** 桌宠仍然可见且可拖动
- **AND** 用户仍可通过托盘打开插件管理器和退出应用

#### Scenario: 当前皮肤插件被禁用

- **GIVEN** 当前皮肤来自一个已启用插件
- **WHEN** 用户尝试禁用该插件
- **THEN** 系统先切换到 `simple-cloud` 或另一套已启用皮肤
- **AND** 只有完成安全切换后才移除原皮肤贡献
- **AND** 桌宠不会显示空白或不可点击窗口

### Requirement: 插件权限和隐私范围必须显式且本地生效

系统 SHALL 在启用插件前校验其权限声明，并 SHALL 只授予宿主明确支持且用户确认过的权限。资源插件默认不需要权限；使用统计等官方能力继续遵守既有本地隐私规则，不得因为插件化新增遥测、云同步、窗口标题、文档名、键盘内容、截图或鼠标轨迹记录。

#### Scenario: 启用无权限皮肤插件

- **GIVEN** 皮肤插件声明空权限列表
- **WHEN** 用户安装并启用它
- **THEN** 系统无需额外权限确认即可加载本地资源
- **AND** 插件不能访问网络或其他插件数据

#### Scenario: 请求未支持的权限

- **GIVEN** 插件声明宿主不支持的网络或任意文件权限
- **WHEN** 用户尝试启用该插件
- **THEN** 系统拒绝启用
- **AND** 在插件详情中显示不支持的权限
- **AND** 不因为该请求发起网络连接或读取额外本地数据
