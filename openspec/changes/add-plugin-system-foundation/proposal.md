## Why

当前桌宠把桌宠窗口、统计采集、快捷面板、大小设置和皮肤资源都直接装配在宿主启动流程中。这样每增加一种能力都要修改 Rust 生命周期、Tauri commands 和 Svelte 页面，用户也无法从一个极简桌宠开始按需安装能力；现在需要建立稳定的插件协议和宿主接缝，为后续官方插件与第三方资源扩展提供基础。

## What Changes

- 建立版本化的插件包 manifest 和本地 `.petpack` 资源包格式，支持插件发现、校验、安装、启用、禁用、卸载和故障状态记录。
- 新增插件注册表和原子安装流程，插件包先在临时目录校验，成功后再进入应用本地插件目录；失败不得破坏当前可用桌宠。
- 将宿主能力整理为稳定接缝，插件只能通过桌宠、面板、设置、存储和权限等受控能力贡献内容，不直接访问 HWND、GDI、SQLite、任意文件或动态 Tauri command。
- 将当前使用统计、快捷面板、桌宠大小设置和默认皮肤整理为官方插件；首次启动只安装并启用一套 `simple-cloud` 默认皮肤，其他皮肤包仅在官方目录中可发现，用户主动安装后才可用。
- 为插件管理提供通用的 Tauri IPC 和中文管理界面，展示已安装、可安装、已启用、已禁用和故障插件，并支持本地 `.petpack` 导入。
- 保留一个核心级默认皮肤兜底，即使插件状态损坏、皮肤包被移除或插件加载失败，桌宠仍可以启动和交互。
- 定义后续 TypeScript/Bun SDK 可以复用的协议类型和资源校验规则，但本次不加载任意第三方 JavaScript、Rust DLL 或其他原生代码。

### 非目标

- 不在本次变更中实现在线账号、云同步、社区分享、支付、遥测或网络插件下载。
- 不在本次变更中允许插件执行任意进程、访问任意网络、读取桌面内容或直接调用 Windows API。
- 不在本次变更中实现插件依赖解析、自动更新、WASM 运行时或独立 sidecar 逻辑插件。
- 不改变现有使用统计口径、隐私边界、SQLite 统计数据模型或桌宠的基础窗口交互。

## Capabilities

### New Capabilities

- `plugin-package-management`: 定义插件包 manifest、资源校验、本地安装目录、注册表、状态迁移、启用/禁用/卸载和故障恢复行为。
- `plugin-host-runtime`: 定义插件宿主、官方预设插件、受控能力接缝、贡献注册和默认皮肤兜底行为。
- `plugin-store`: 定义本地官方插件目录、已安装插件管理界面、`.petpack` 导入和安装结果反馈；首版不要求在线目录。

### Modified Capabilities

无。现有桌宠外壳、快捷面板、大小设置和使用统计的既有规格不在本次变更中改变其用户可观察的采集或交互规则；它们只会在实现层被重新装配为官方插件。

## Impact

- Rust 启动和生命周期：从 `lifecycle.rs` 的具体功能装配迁移到插件宿主与官方插件注册。
- Rust 桌宠窗口和资源加载：保留 `pet_window.rs` 的 Win32、DPI、透明命中和动画实现，通过皮肤资源提供者读取当前已安装资源，而不是固定三项 `include_bytes!` 清单。
- Tauri IPC：保留编译期注册的通用插件命令，避免为动态插件生成新的 command；新增插件 DTO、错误码和权限检查。
- Svelte/TypeScript：增加插件管理和官方目录视图，并将快捷面板逐步改为渲染宿主提供的声明式贡献。
- 本地数据：新增版本化插件注册表、插件安装目录和插件独立存储命名空间；现有 `pet-preferences.json`、`pet-skin-preferences.json` 与使用统计数据库保持兼容。
- 依赖与资源：首版继续使用 Tauri 2、Rust、Svelte、TypeScript、Bun 和 SQLite，不引入动态脚本运行时；后续 SDK 可在 Bun 工具链中独立发布。

## Privacy Impact

插件元数据、安装状态和插件设置只保存在本地。插件宿主默认不提供网络、任意文件、窗口标题、文档名、键盘内容、截图、鼠标轨迹或统计数据库直读能力；使用统计仍由官方插件遵循现有本地采集和隐私规则。插件安装不会自动发送遥测或选择历史。
