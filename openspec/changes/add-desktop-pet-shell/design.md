## 背景

现有代码已经包含 Rust 软件活动采集器、SQLite 仓储、Tauri 托盘/单实例生命周期，以及一个按需创建的 Svelte 统计面板。问题不在统计功能本身，而在启动和窗口模型：当前生命周期直接创建统计面板，产品因此表现为普通统计器。

桌宠需要全天可见，但项目仍要求较低内存。按照 Tauri 2.9 的窗口能力，普通 `WebviewWindow` 可以透明和无边框，但仍会常驻 WebView2；Tauri 原生无 WebView 的 `WindowBuilder` 目前需要 unstable feature，而且仍需自行完成像素绘制。Windows 分层窗口可以直接提供逐像素透明、命中测试和较低资源，因此桌宠本体采用原生 Win32，统计面板继续使用成熟的 Tauri WebView。

## 目标与非目标

**目标：**

- 让启动后的第一视觉信号是桌宠角色，而不是统计页面。
- 桌宠本体不创建 WebView2，并保持逐像素透明和低资源待机。
- 复用现有采集器、数据库和统计面板，不重写已经工作的业务逻辑。
- 把 Windows unsafe 代码集中到一个小模块，窗口几何和交互判断保持可测试。
- 角色资产与窗口逻辑解耦，后续可以替换外观而不修改采集和统计代码。

**非目标：**

- 在第一版建立通用动画引擎、Live2D 运行时或皮肤插件系统。
- 为非 Windows 平台模拟同一套原生桌宠窗口。
- 用桌宠窗口呈现复杂文字、菜单或统计；复杂 UI 仍由现有统计面板负责。

## 技术决策

### 新建独立 change，不重写统计 change 的历史意图

`add-daily-app-usage-tracking` 保留为数据能力和统计面板基础，`add-desktop-pet-shell` 负责产品主体验和两者集成。这样可以保留已有实现和测试，同时明确桌宠才是产品入口。统计 change 的中文文档会补充说明它是附属能力，但不把其实现任务混入桌宠任务。

### 使用 Win32 分层窗口渲染桌宠

新增 `pet_window` Rust 模块，在独立线程中注册窗口类并运行原生消息循环。使用 `CreateWindowExW` 创建 `WS_POPUP` 窗口，并设置：

- `WS_EX_LAYERED`：通过 `UpdateLayeredWindow` 提供逐像素 alpha。
- `WS_EX_TOOLWINDOW`：不在任务栏显示。
- `WS_EX_TOPMOST`：保持在普通应用窗口之上。
- `WS_EX_NOACTIVATE`：单击和拖动桌宠时不抢走当前应用焦点。

窗口没有标题栏、边框和系统阴影。透明 PNG 解码后转换为预乘 alpha 的 BGRA DIB，使用 `UpdateLayeredWindow` 一次提交整帧。该方案比透明 WebView 更接近桌宠窗口语义，也避免全天保留 WebView2 进程和内存。

考虑过的替代方案：

- 透明 `WebviewWindow`：实现最快，也方便 CSS 动画，但与“占比特别小”的目标冲突，并且透明矩形的命中行为更难精确控制。
- Tauri 原生 `WindowBuilder` + `softbuffer`：没有 WebView，但依赖 unstable feature，逐像素透明和 Windows 命中仍需原生处理。
- 独立宠物进程：隔离性更强，但会增加进程生命周期、IPC 和打包复杂度，当前没有必要。

### 使用一个原创、可替换的本地 PNG 角色

第一版角色采用圆形小机器人：青绿色主体、珊瑚色细节和暖黄色指示灯，轮廓清晰，避免只有单一色相。生成源文件经过透明背景处理和 alpha 检查后，保存到 `src-tauri/assets/pet.png`，并通过 `include_bytes!` 打包进可执行文件，不依赖运行时文件路径或网络。

角色原图保持较高分辨率，启动时按照当前 DPI 缩放到约 200×220 逻辑像素。PNG 解码只启用 `image` crate 的 PNG feature，避免引入不需要的格式解码器。

### 预计算低频待机帧

启动或 DPI 改变时，从同一张角色图预计算少量待机帧：轻微上下偏移并在垂直方向做约 1% 的呼吸缩放。消息循环以约 4 FPS 切换这些帧，完整周期约 2.5 秒；拖动或隐藏时暂停动画。

每个 240×240 左右的预乘 BGRA 帧只占约 225 KiB，8 帧总量低于 2 MiB。预计算避免在每个计时器 tick 解码或缩放图片。待机动画只改变角色图形，不改变窗口外部尺寸，防止布局和鼠标命中区域跳动。

### 用 alpha 命中区分透明区域和角色区域

`WM_NCHITTEST` 将屏幕坐标转换为桌宠客户区坐标，并读取当前帧对应像素的 alpha：

- alpha 低于阈值时返回 `HTTRANSPARENT`，让下方桌面或应用接收输入。
- alpha 达到阈值时返回 `HTCLIENT`，由桌宠处理点击和拖动。

`WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`，避免打断用户正在使用的软件。alpha 命中帮助函数使用普通 Rust 数组和坐标输入，可以通过单元测试验证边界、透明像素和可见像素。

### 明确区分单击和拖动

在 `WM_LBUTTONDOWN` 时保存指针和窗口起点并捕获鼠标。`WM_MOUSEMOVE` 超过 Windows 系统拖动阈值后进入拖动状态，用 `SetWindowPos` 移动窗口；`WM_LBUTTONUP` 时释放捕获：

- 没有超过阈值时，通知 Tauri 主线程打开或关闭桌宠下方的快捷面板。
- 已经拖动时，只修正并保存位置，不打开统计。

桌宠线程通过 `AppHandle::run_on_main_thread` 请求快捷面板控制器，所有 Tauri 窗口创建仍发生在主线程。快捷面板和完整统计面板分别使用稳定标签，因此重复单击只切换快捷面板，不会创建重复窗口。

### 在物理坐标中保存位置并根据工作区修正

桌宠位置保存到应用本地数据目录的 `pet-state.json`，只包含版本和物理像素坐标。每次拖动结束和正常退出时使用临时文件加 rename 的方式原子写入。隐藏状态不跨重启保存，正常启动始终显示桌宠。

恢复时枚举显示器工作区并检查桌宠矩形是否完整可见。有效位置直接使用；无效位置或没有状态文件时，使用主显示器工作区右下角并保留 24 个逻辑像素边距。拖动结束、显示桌宠以及收到 DPI/显示器变化后都执行同一套 clamp 函数。

窗口和 DPI 逻辑保持在 Windows 适配层，几何函数以显示器矩形、窗口尺寸和候选坐标为输入，可在不创建 HWND 的情况下测试。

### 通过 PetHandle 管理原生线程生命周期

`PetHandle` 保存窗口线程 ID、原生窗口句柄和可见状态，并向桌宠线程发送 `Show`、`Hide`、`EnsureVisible`、`SavePosition`、`Shutdown` 命令。实际传递使用 `PostMessageW` 的 `WM_APP` 范围消息，避免额外异步运行时。

Tauri setup 顺序调整为：

1. 打开本地数据目录并启动现有采集器。
2. 尝试启动 `PetHandle`。
3. 安装中文托盘菜单。
4. 不自动创建统计面板。

如果角色资产解码或原生窗口创建失败，setup 不终止整个应用：采集器和托盘继续运行，“打开使用统计”和“退出”仍可用，也不会留下透明拦截窗口。

### 更新托盘、单实例和产品身份

托盘包含动态的“显示桌宠/隐藏桌宠”、“打开使用统计”和“退出”。左键单击托盘默认显示桌宠；完整统计入口由托盘菜单或快捷面板触发。第二实例回调发送 `EnsureVisible`，不再直接打开统计窗口。

Tauri `productName`、应用标识展示、统计面板标题和托盘提示改为“小桌宠”语义。现有 Svelte 页面标题改为“使用统计”，正文继续保持中文。关闭统计面板仍销毁 WebView，桌宠和采集器继续运行。

### 保持隐私和资源预算不变

桌宠模块不访问采集器快照、桌面像素或窗口标题。拖动过程中只在内存保存起点和当前位置，持久化时只写最终窗口坐标。角色资产完全本地打包。

release 验收时在统计面板关闭、桌宠动画运行状态测量五分钟 CPU 和私有工作集。若原生待机仍超过 1% CPU，首先降低动画帧率或只在前台桌面可见时重绘；不得改回常驻 WebView 来规避实现问题。

## 风险与取舍

- [Win32 分层窗口包含较集中的 unsafe 代码] -> 把原生调用限制在单个模块，用 RAII 释放 HDC、HBITMAP、计时器和窗口，并让几何/命中判断保持纯函数。
- [生成角色的透明边缘可能带色边或大面积半透明] -> 使用平坦色键生成、专用脚本去背景，并检查 alpha 通道、透明四角和主体覆盖率。
- [DPI 和多显示器坐标容易混用] -> 内部统一使用物理像素，只有默认边距和目标尺寸从逻辑单位按 DPI 转换，并用多组显示器矩形测试。
- [原生窗口线程异常可能让桌宠消失] -> 采集器和托盘不依赖桌宠初始化成功；托盘统计入口和退出始终可用。
- [WS_EX_NOACTIVATE 下鼠标行为与普通窗口不同] -> 在 Windows release 构建中手工验证单击、捕获、拖动、透明穿透和不抢焦点。
- [单张静态角色的动画表现有限] -> 第一版只承诺克制的待机呼吸；后续用独立 change 引入多帧或 Live2D，而不扩张本次范围。

## 迁移计划

1. 保留现有 SQLite 数据和采集器接口，不执行数据库迁移。
2. 新增角色资产、桌宠状态文件和原生窗口模块。
3. 修改生命周期，使新版本首次启动显示桌宠，不再自动打开统计面板。
4. 第一次运行没有 `pet-state.json` 时，把桌宠放在主显示器工作区右下角；不会影响已有使用记录。
5. 回滚到旧版本时，旧代码忽略 `pet-state.json`，仍可继续读取同一个统计数据库。
